# #317 wait-shape qualification

This package implements the result-independent lock and bounded retained F0 audit of
[Issue #322](https://github.com/lisbun/lisjong-arena/issues/322).

## Ownership boundary

Canonical structural wait and wait-mechanism semantics remain owned by lisjong:

```text
lisjong.belief.exact_wait_ground_truth.exact_hand_belief_with_waits()
```

Arena adds only the bounded Stage-M0 projection:

```text
canonical Level-2 mechanism truth
  -> TANKI / SHANPON / KANCHAN / PENCHAN / RYANMEN
  -> KOKUSHI descriptive channel
```

RYANMEN is the logical OR of the canonical low-side and high-side channels.
The projection is multi-label. KOKUSHI-only is valid: all five ordinary shape
labels may be zero while the descriptive KOKUSHI channel is one.

## #258 reuse

The existing `stage_a0_tenpai_feasibility` package remains unchanged.
Its `RIICHI_EXCLUDED` meaning is still the non-riichi Tenpai target boundary.

#322 reuses the same-state hidden snapshot, public/private binding, physical
inventory checks, stable 13-equivalent checks, and retained sidecar payload.
It does not reinterpret the #258 Tenpai label.

## Pre-result lock

`wait_shape_qualification.protocol` freezes:

- current Heuristic Champion source and exact lisjong revision;
- `RiichiState.ACCEPTED` as the public-riichi eligibility state;
- pilot seeds 2000..2095 (96 hanchan);
- F1/F2 support thresholds;
- fresh scientific TRAIN / SELECT / EVAL populations;
- A/M, probe, and offline-EVAL result-independent constants;
- `DEFENSE DIAGNOSTIC NOT APPLICABLE`, because current lisjong analysis
  contracts expose defensive branch information but not an unambiguous
  current-teacher defense-action-change counterfactual suitable for a hard gate.

The qualification pilot is not generated by this change.
A/M training and interactive evaluation are also out of scope.

## Retained F0 audit (#325)

```powershell
python -m lisjong_arena.wait_shape_qualification --sidecar C:\artifacts\retained-sidecar --output C:\artifacts\wait-shape-f0.json
```

Supply one complete #258 retained-augmentation sidecar from the locked retained
dataset, containing only TRAIN seeds 245..264 (a previously retained subset is
allowed). The command does not select seeds, replay games, inspect F1/F2, or
generate new labels outside the prior `RIICHI_EXCLUDED` population. Audit the
preselected sidecar once; do not select another subset based on its outcome.

The loader checks the existing manifest/digests and the F0 seam additionally
requires three distinct ordered opponent cells per decision, one public-row
digest and dealer, compatible source/route, and the locked current dependency
revisions. Original #258 provenance and canonical implementation identity are
preserved separately from the current audit execution provenance. Historical
sidecars need not have the current teacher revision: they are technical evidence,
not the scientific teacher population.

`same_state_cells` counts examined cells carrying both hidden hand and meld state
with consistent public/private riichi binding. This relies on #258's co-emission
checks (decision point, seat mapping, public meld equality and public-row digest);
it is not an independent reconstruction of historical hidden state. Missing state
is reason-coded, never filled in. DECLARED cells remain in examined counts but
cannot produce accepted-riichi labels. Non-riichi cells are not relabelled.

The report contains all unavailable `WaitShapeAvailability` codes, including
invalid inventory, unstable 13-equivalent state, builder and projection failures.
Multi-positive means more than one of the six channels. All-six-channel-zero
counts canonical `NO_STRUCTURAL_WAIT` results; inconsistent mechanism projection
is instead `INVALID_SEMANTIC_PROJECTION`, never an emitted zero target.
KOKUSHI-only labels count as valid demonstrations. The exact F0 pass rule requires
zero binding, builder and semantic-projection failures and at least one label.

The canonical JSON `arena-retained-wait-shape-f0-v1` report binds the #322 protocol
lock hash (including teacher, projection and eligibility), source sidecar identity,
public-row/schema identities and execution revisions. `load_f0_report()` rejects
unknown fields, incompatible identities, non-integer/negative counts and
contradictory classification/totals. Output uses exclusive creation; an existing
report is never overwritten. Both scientific outcomes are successful CLI runs;
malformed/incompatible input raises and produces no report. Reports contain only
aggregates and provenance, never concealed hands. Store run artifacts outside Git.
